# Translations

`aisooq-connector.pot` is the template translators work from. Drop compiled
`aisooq-connector-<locale>.mo` files here (with their `.po` sources);
`load_plugin_textdomain()` in `aisooq-connector.php` reads this directory.

## Regenerating the template

Whenever you add, change or remove a translatable string:

```sh
bin/make-pot.sh      # or: composer i18n
```

It uses wp-cli if you have it, otherwise Docker. **The wp-cli version is pinned
in the script**, because 2.11 and 2.12 emit different bodies for this plugin —
a template generated by one and checked by the other differs by around ninety
lines with no string change behind it.

`tests/test-i18n.php` fails if a translatable string in the source is missing
from the template, so a forgotten regeneration is caught in CI on every
supported PHP version. That test needs no wp-cli.

## Two deliberate choices

**No `#:` file:line references.** With them, 544 of the template's lines are
location comments and any edit that shifts a line in `includes/` rewrites
hundreds of them — the template would go stale on commits that change no string
at all. Translators lose the file:line context; in exchange the file only moves
when the strings do.

**`POT-Creation-Date` and `X-Generator` are blank.** Both change on every run.
Left in, regenerating an unchanged tree produces a diff, and nobody can tell a
real change from a timestamp.

## The Bangla checkout messages are not here

The shopper-facing checkout messages (`msg_courier`, `msg_duplicate`, and the
rest) ship as Bangla **option defaults**, not as `__()` calls, so they are not
in this template and cannot be translated through it. That is deliberate: they
are operator-editable content, changed in **AI Sooq → Settings → Checkout
messages** on each store, not translations of a fixed English original.
